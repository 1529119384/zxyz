- 每个 composable 以 export function 形式返回包含 ref/computed 状态和方法的对象，通过 options 参数注入依赖（如 spaceContext、getTeamId 等回调），保持纯函数风格。
- API 层统一使用 request.get/post/patch/delete 发起请求，并在返回前通过 models 中的 mapXxxEntries 函数将后端字段映射为前端标准结构（如 originalName→fileName、fileType→type）。
- 组件间通信通过 defineProps/defineEmits 声明接口，复杂状态通过 composables 组合而非全局 store，需要跨组件共享的状态（如 currentId）通过 Pinia store 或 provide/inject 传递。
- 错误处理统一通过 handleBusinessError/isHandledByGlobalError 包装，网络异常和业务异常分离，登录失效等由全局请求层处理的错误不再向组件抛出。
- 文件类型判断使用 filePresentation.js 中的 normalizeFileType/createDisplayFileEntry 生成统一展示对象，category 通过扩展名推断或后端传入，图标通过 getFileIcon 解析。
