模块采用清晰的分层结构：
- API 层：`api/im.js` 与 `api/teamIm.js` 分别封装 IM 核心接口与团队协作扩展接口，统一通过 `utils/imRequest.js`（基于 `createApiClient`）发起 HTTP 请求。
- 状态管理层：`store/chat.js` 是核心 Pinia store，内部按职责拆分为 conversationDomain、messageDomain、notificationDomain、realtimeDomain 四个领域子模块（位于 `store/im/`），通过依赖注入对象 `teamDeps` 延迟绑定 teamStore，避免循环依赖。
- 实时通信：`utils/imWebSocket.js` 提供带心跳、指数退避重连、Bearer ticket 认证的 WebSocket 客户端，状态常量 `IM_WS_STATUS` 由 store 消费。
- 组合式函数：`composables/useImWorkspace.js` 负责团队切换与工作区初始化；`composables/useSendToConversation.js` 封装文件卡片发送到会话的交互流程。
- 展示模型：`models/imPresentation.js` 集中处理消息内容解析、状态文本映射与时间格式化。
- 常量定义：`constants/conversationTypes.js` 与 `constants/messageStatus.js` 统一定义会话类型与消息状态枚举。
- 解耦机制：`store/plugins/chatBridge.js` 作为 Pinia 插件在 chatStore 实例化时自动注入 teamStore，实现 chat 与 team 模块的松耦合。
