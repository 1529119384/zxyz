- API 文件采用「一个文件对应一组相关接口」的组织方式，每个导出函数直接返回 `request.get/post/patch` 调用结果，不额外包装 Promise。
- Composable 统一通过 reactive/ref 管理表单状态，使用 try/catch/finally 包裹异步操作，在 finally 中重置 loading 标志，并通过 `handleBusinessError` 统一处理业务异常。
- Store 中的敏感数据（email、phone、roles、permissions）与显示数据分离：`normalizeDisplayUser` 仅保留 id、username、name、avatar、defaultTeamId、verified 标记，并通过 separate localStorage key 持久化。
- 所有用户交互反馈统一使用 Element Plus 的 `ElMessage.success/warning`，错误信息通过 `handleBusinessError(error, 'xxx')` 集中处理。
- Composable 通过参数注入依赖（如 `{ currentUserStore, applyProfile, contactForm }`），而非内部直接 import store，便于测试与复用。
- 异步初始化方法（如 `ensureSessionReady`、`ensureProfileLoaded`）支持 `force` 选项强制刷新，并通过 pending 变量防止重复请求。
