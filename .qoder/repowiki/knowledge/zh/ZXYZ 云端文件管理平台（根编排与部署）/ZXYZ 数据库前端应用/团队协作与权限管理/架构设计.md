模块按功能分层组织：
- 状态层 `store/team.js` 通过 Pinia 定义全局 team store，内部使用事件总线（`createEventEmitter`）解耦 `teamDomain` 与 `permissionDomain`，所有 state 以 `readonly` 暴露，方法由 domain 组合后统一导出。
- 上下文层 `composables/useCurrentSpaceContext.js` 基于路由 meta 自动判断个人/团队/项目空间类型，并通过 Vue provide/inject 模式向子树注入 `currentSpaceContextKey`，同时导出 `normalizeSpaceRequestParams` / `resolveSpaceRequestParams` 标准化请求参数。
- 业务逻辑层 `composables/useTeamPermissionActions.js` 封装角色 CRUD 与成员角色分配等交互流程，复用 `handleBusinessError` 统一错误处理。
- API 层 `api/team.js`、`api/adminTeam.js`、`api/permission.js` 分别对应团队基础操作、管理员后台接口与系统权限接口，均基于 `@/utils/request` 封装。
- 模型与常量 `models/space.js`、`models/permission.js`、`constants/teamPermissions.js` 集中定义空间类型枚举、权限分组树构建与权限码常量。
- UI 组件层 `TeamSelectDialog.vue`、`TeamSettingDrawer.vue`、`TeamSwitcher.vue`、`RoleManagementPanel.vue` 为纯展示与用户交互组件，通过 props/emits 与 store 或 composables 通信，不直接调用后端 API。
依赖方向单向向下：组件 → composables → store/domain → api → utils，禁止反向依赖。
