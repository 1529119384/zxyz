- 后端 API 统一使用 `Result<T>` 包装响应，成功码固定为 `code: 1`，前端通过 `payload?.code === 1` 判断成功。
- 错误码按范围分组（1 成功、4000 参数、4010 认证、4030 权限、4090 状态冲突、5000 系统错误），由 `ErrorCode` 常量类集中管理。
- 服务间 HTTP 调用通过 `X-Internal-Service-Token` 和 `X-Request-Id` 两个 Header 完成鉴权与链路追踪。
- 大多数服务采用传统分层 `controller/service/impl/mapper/entity`，仅 `email-service` 和 `im-service` 采用 DDD 风格 `interfaces/application/domain/infrastructure`。
- DTO↔Entity 转换统一使用 MapStruct 的 `*Converter`/`*Assembler` 类，而非手动赋值。
- 前端测试文件 import 顺序严格分三组：vitest/vue/pinia → vi.mock() 调用 → 业务导入，mock 声明紧挨无空行。
